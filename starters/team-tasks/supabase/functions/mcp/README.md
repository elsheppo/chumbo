# Team Tasks MCP function

This Edge Function is the application's MCP server. It was generated by
`chumbo init --auth oauth` and only `capabilities.ts` is hand-written.

- `index.ts`, `deno.json`, and `index_test.ts` are Chumbo's generated wiring.
  `npx chumbo setup --resume --function mcp` re-checks them and reports what is
  left to do; it never overwrites `capabilities.ts`.
- `capabilities.ts` registers `list_teams`, `list_tasks`, `create_task`, and
  `update_task`. Every query goes through `ctx.supabase`, which carries the
  connected user's access token, so the RLS policies in
  `supabase/migrations/` decide what each agent can see and change.
- `../_shared/database.types.ts` is generated by `npm run types` and shared with
  the web app.

Prove changes with:

```sh
deno task --config supabase/functions/mcp/deno.json check   # types
deno task --config supabase/functions/mcp/deno.json test    # OAuth challenge
npm run test:isolation                                       # RLS, needs `supabase start`
```

Deploy with `supabase functions deploy mcp --no-verify-jwt`. The function
verifies tokens itself and returns standards-shaped OAuth challenges, which the
platform's JWT gate would otherwise replace.
